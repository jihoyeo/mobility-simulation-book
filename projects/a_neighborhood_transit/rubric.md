# 기말 프로젝트 채점표 — 내가 사는 동네의 대중교통

제출 전에 스스로 체크하세요. 상세 설명은 교재 「기말 프로젝트」 장에 있습니다.

## 데이터 준비 (20점)

- [ ] 대상지를 골랐고 왜 골랐는지 적었다 (3)
- [ ] 경계로 GTFS 를 잘랐고 자르기 전후 수를 표로 냈다 (5)
- [ ] `route_type` 분포를 TAGO 코드로 해석했다 (4)
- [ ] 첫차·막차 시각을 24시 넘는 표기까지 처리해 구했다 (3)
- [ ] **데이터에서 이상한 점을 하나 이상 찾아 적었다** (5)

마지막 항목이 배점이 큽니다. 이름 중복, 하루 한 번뿐인 노선, 엉뚱한 좌표, 경계에서 끊긴 노선 등 무엇이든 좋습니다. 들여다봤는지가 여기서 드러납니다.

## 경로 탐색 정확도 (20점)

- [ ] 자기 RAPTOR 로 O-D 100쌍을 계산했다 (6)
- [ ] 도달 불가 쌍이 왜 생겼는지 확인했다 (4)
- [ ] 엔진 또는 지도 앱과 10쌍 이상 대조한 표를 냈다 (6)
- [ ] 차이가 큰 쌍 3개의 원인을 설명했다 (4)

## 시나리오 설계 (20점)

- [ ] 6주차에 적은 불편함과 시나리오가 이어진다 (5)
- [ ] GTFS 를 실제로 고쳤고 고친 파일을 제출했다 (7)
- [ ] 개선 전후를 **같은 O-D** 로 비교했다 (5)
- [ ] 실현 가능한 안이다 (버스가 못 다니는 길이 아니다) (3)

## 지표 해석 (25점)

- [ ] 통행시간·차내·도보·대기·환승·요금 여섯 지표를 냈다 (5)
- [ ] **평균과 함께 중앙값·90분위를 냈다** (5)
- [ ] 분포 그림이 있다 (4)
- [ ] **개선의 대가를 적었다** — 차량 몇 대 더, 운영비 얼마 (6)
- [ ] 한계 절이 있다. 무엇을 가정했고 무엇을 넣지 않았는지 (5)

## 발표와 재현성 (15점)

- [ ] 8분 안에 결론이 전달된다 (5)
- [ ] 첫 슬라이드에 한 문장 결론이 있다 (3)
- [ ] 코드를 받아 위에서부터 다시 돌릴 수 있다 (5)
- [ ] 절대 경로나 손으로 고친 중간 파일이 없다 (2)

## 감점

| | |
|---|---|
| −5 | 서비스율 없이 평균 대기시간만 보고 |
| −5 | 개선 효과만 적고 대가를 적지 않음 |
| −5 | 한계 절이 없음 |
| −5 | 코드가 다시 돌아가지 않음 |
| −3 | 그림에 한글이 깨져 있음 |

## 가점 (최대 +5)

| | |
|---|---|
| +3 | 실제로 그 노선을 타 보고 시뮬레이션 결과와 비교 |
| +2 | 지도 앱과 10쌍 이상 대조하고 차이의 원인을 규명 |
| +3 | 자기 지역 데이터에서만 나오는 문제를 찾아 해결 |
