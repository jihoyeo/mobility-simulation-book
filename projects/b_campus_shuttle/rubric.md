# P-실무프로젝트 채점표 — 교내 셔틀버스

팀 제출입니다. 상세 설명은 교재 「P-실무프로젝트」 장에 있습니다.

## 수요 모델링 (20점)

- [ ] 이용자 수를 추정했고 근거를 적었다 (5)
- [ ] 교시 시간표를 실제 학사일정에서 확인해 넣었다 (3)
- [ ] 출발 지점 비율의 근거를 댔다 (4)
- [ ] **가정을 전부 목록으로 적었다** (4)
- [ ] 주요 가정 하나 이상에 대해 민감도를 봤다 (절반/두 배) (4)

## 노선 설계 타당성 (20점)

- [ ] 정류장을 골랐고 왜 그 지점인지 적었다 (5)
- [ ] 정류장 사이 소요시간을 최단경로로 계산했다 (5)
- [ ] 경사·정차 시간을 반영했다 (3)
- [ ] **실제로 버스가 다닐 수 있는 길이다** — 지도에서 확인 (4)
- [ ] 필요한 차량 대수를 왕복 시간과 배차간격으로 계산했다 (3)

## 실험 설계 (20점)

- [ ] 고정노선과 수요응답을 **같은 수요**로 비교했다 (6)
- [ ] 차량 대수를 4단계 이상 훑었다 (4)
- [ ] **seed 를 3회 이상 반복했다** (5)
- [ ] 표준편차를 보고 시나리오 간 차이가 유의한지 판단했다 (5)

## KPI·파레토 분석 (25점)

- [ ] 서비스율·대기 중앙값·90분위·가동률을 냈다 (5)
- [ ] **첨두와 비첨두를 나눠 봤다** (7)
- [ ] 파레토 프론트를 그렸다 (5)
- [ ] 어느 안을 왜 고르는지 근거를 댔다 (5)
- [ ] 한계 절이 있다 (3)

## 발표 (15점)

- [ ] 15분 안에 결론이 전달된다 (5)
- [ ] 첫 슬라이드에 한 문장 결론 (3)
- [ ] **아무나 지목해 질문했을 때 답할 수 있다** (5)
- [ ] 코드를 받아 다시 돌릴 수 있다 (2)

## 채점에 쓰는 지표

| 지표 | 어디서 |
|---|---|
| `service_rate` | `kpi_table()` |
| `wait_p50`, `wait_p90` | 같음 |
| `utilization` | 같음 |
| `empty_share` | 같음 |
| 차량-시간 | 차량 대수 × 운영 시간 |

## 감점

| | |
|---|---|
| −5 | 서비스율 없이 대기시간만 제시 |
| −5 | seed 한 번만 돌린 결과로 우열 주장 |
| −5 | 첨두·비첨두를 나누지 않고 하나의 결론만 |
| −5 | 실제로 못 다니는 경로를 노선으로 제시 |
| −3 | 가정 목록이 없음 |

## 가점 (최대 +5)

| | |
|---|---|
| +3 | 실제 셔틀 운행을 관찰해 수요 추정을 검증 |
| +3 | 정원 제약을 제대로 넣은 수요응답 구현 |
| +4 | 첨두 고정노선 + 비첨두 수요응답 혼합안을 설계하고 효과를 보임 |

정원을 못 넣었다고 감점하지 않습니다. **한계로 적으면 됩니다.** 대충 넣고 넣었다고 하는 것이 더 나쁩니다.
