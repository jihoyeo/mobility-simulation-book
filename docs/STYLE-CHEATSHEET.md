## 문단을 쓴 뒤 두 번 묻습니다

1. **이식성** — 다른 장, 다른 분야 교재에 붙여도 말이 되는가? → 되면 삭제
2. **정보량** — 숫자·고유명사·코드 식별자·파일명을 지우면 뭐가 남는가? → 없으면 삭제

## 장 첫머리와 개념 설명

장 첫머리는 다루는 대상의 **정의와 용도**부터 설명합니다. 실제 활용처와 이 장에서 배울 범위를 잇습니다.
데이터 표준을 다루면 구성 파일, 각 파일의 정보와 대표 필드, 식별자 관계를 실습 전에 정리합니다.
GTFS라면 정의·Google 지도 등의 활용처 → 파일 구성 → 각 표의 예시 행 → 표 연결 → 시간표 작성 순서입니다.

개별 개념은 구체적 질문 → 작은 표·도식과 손계산 → 결과 예상 → 노트북 실행·대조 → 조건 변경 순서로 설명합니다.
본문은 원리와 해석을, 노트북은 실행 코드를 중심으로 씁니다. 실습에서 사용할 새 개념을 코드로 먼저 던지지 않습니다.
수업 회차·시간 배분·수업 종료 안내는 본문과 노트북에 넣지 않습니다.

## 예산

- 볼드: 1000자당 3개 · 절당 문장 볼드 1개 · 최대 40자 (용어는 12자 이하 명사)
- `<u>`: 전면 금지
- 참고·주의: 표준 Markdown 인용문으로 표시합니다. MyST admonition은 사용하지 않습니다.
- 문장: 85자 경고 / 120자 오류
- `의` 연속 2개까지

## 표기

- 함수·컬럼·파일·패키지 이름은 **반드시** 백틱
- 최초 1회 `한국어(english)`, 이후 한국어만
- 배차(디스패치 X) · 재배치 · 보정 · 통행(여행 X) · 노드/엣지 · 공차 운행
- 인사이트 X, 솔루션 X
- 절 제목은 개념·분석 대상을 나타내는 한국어 명사구로 씁니다. GTFS·RAPTOR 등 고유 명칭은 유지합니다.
- 질문형·대화체·활동 지시형 제목을 피합니다. `승객 한 명 따라가기` → `탑승 가능 운행과 도착시각 계산`

## 그림·코드

- 그림은 `![설명](../figures/파일.svg)` + 일반 문단 캡션. MyST 지시문·옵션·역할은 사용하지 않습니다. 일반 Markdown 프리뷰에서 읽히는지 확인합니다.
- iframe·raw HTML은 정적 그림·결과표와 표준 Markdown 링크로 대체합니다.
- 실행 코드·함수 사용법·명령·구현 과제는 실습 노트북에 둡니다. 강의 본문에는 개념·수식·결과·해석을 남깁니다. Jupytext·kernelspec 메타데이터를 추가하지 않습니다.
- 노트북 코드 셀: 위에 왜 하는지 1~3문장, 아래에 출력 해석 1~2문장. 해석 없는 셀은 미완성
