## 문단을 쓴 뒤 두 번 묻습니다

1. **이식성** — 다른 장, 다른 분야 교재에 붙여도 말이 되는가? → 되면 삭제
2. **정보량** — 숫자·고유명사·코드 식별자·파일명을 지우면 뭐가 남는가? → 없으면 삭제

## 문체

- **합니다체 통일.** `~합니다` / `~입니다` / `~까요?` / `~해 봅시다`
- 금지: `~한다` `~이다` `~하자` `~하세요`

## 개념 도입 5단계

구체적 질문(지명+숫자) → 5~15줄 최소 코드 → 출력을 본문에 옮겨 적고 한 문장으로 읽기 → 막히는 곳 노출 → 일반화하고 **그때** 이름 붙이기

## 즉시 삭제

| | |
|---|---|
| 격상 어휘 | 혁신적, 패러다임, 핵심 메시지, 시급, 대두, 부각, 획기적, 게임 체인저 |
| 근거 없는 예측 | ~할 것으로 예상됩니다, ~될 전망입니다, 이미 입증되었습니다 |
| 형용사 삼단 나열 | "효율적이고, 지속 가능하며, 공평한" |
| 부정 정의 | "단순한 X가 아니라 Y입니다" |
| 대칭 장단점 불릿 | `- **장점**: … / - **단점**: …` |
| 빈 마무리 | 문단 끝 문장에 숫자·백틱·고유명사가 없으면 지웁니다 |
| 접속·수식 부사 | 또한, 더욱이, 나아가, 이를 통해, 매우, 다양한, 효과적으로 |
| 번역투 | ~되어진, ~에 있어서, ~을 가지고 있다, ~을 통해서 |

## 예산

- 볼드: 1000자당 3개 · 절당 문장 볼드 1개 · 최대 40자 (용어는 12자 이하 명사)
- `<u>`: 전면 금지
- admonition: 절당 1개, `note`/`tip`/`warning` 3종만
- 문장: 85자 경고 / 120자 오류
- `의` 연속 2개까지

## 표기

- 함수·컬럼·파일·패키지 이름은 **반드시** 백틱
- 최초 1회 `한국어(english)`, 이후 한국어만
- 배차(디스패치 X) · 재배치 · 보정 · 통행(여행 X) · 노드/엣지 · 공차 운행
- 인사이트 X, 솔루션 X
- 절 제목은 한글 (`1.2 The Necessity of Simulation` → `1.2 왜 시뮬레이션이 필요한가`)

## 그림·코드

- `{image}` 금지 → `{figure}` + `:name:` + 캡션. 본문에서 참조하지 않는 그림은 삭제
- raw HTML 레이아웃(`<div style=`, `<p style=`) 금지
- 코드 셀: 위에 왜 하는지 1~3문장, 아래에 출력 해석 1~2문장. 해석 없는 셀은 미완성
