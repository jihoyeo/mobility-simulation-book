# Assignment 2 배포 준비

학생용 과제안은 [assignment_2.ipynb](../assignment/assignment_2.ipynb)입니다.
송파구 과제용 데이터와 [통합 과제 노트북](../assignment/assignment_2.ipynb)를 준비했습니다.
30건 모두 택시·대중교통 경로를 검증했고, 학생용 노트북을 처음부터 실행했습니다.
브라우저에서 재생·시각 선택·사람 선택·PNG 저장과 도착 인원도 확인했습니다.

데이터는 `assignment/data/`, 제공 함수는 `smartmob/assignment2.py`에 있습니다.
강사용 참조 CSV·경로·재생 HTML·검증 기록은 `outputs/assignment2_instructor/`에 생성합니다.
재생성 방법과 원본 체크섬은 [데이터 설명서](ASSIGNMENT2_DATA.md)와 ZIP 안의 `manifest.json`에 있습니다.

확인된 제한: 도로 수집일 미기록, 서울 캐시 밖 경기도 도로 불완전, 2013년 행정경계 사용.
이 제한은 학생용 안내와 데이터 설명서에도 적었습니다.

## 데이터 준비 기준

1. 송파구 경계와 주변을 포함한 OSM 자동차 도로망을 확보합니다.
   수집일·출처·이용 조건·좌표계·추출 범위를 기록하고 방향과 엣지 형상을 보존합니다.
2. GTFS 원본의 유효기간 안에서 평일 하루를 선정합니다.
   `calendar`와 `calendar_dates`의 예외를 반영한 운행만 남깁니다.
   송파구 정류장만 잘라 운행을 끊지 않고 필요한 주변 환승과 전체 정류장 순서를 보존합니다.
   저장소의 기존 로더는 `calendar_dates`를 기본으로 읽지 않으므로 전처리에서 별도로 처리합니다.
3. 실제 O-D가 지정되지 않으면 송파구 내부에서 합성 좌표 쌍을 생성합니다.
   실제 관측 통행이 아니라는 설명과 난수 시드 42를 기록합니다.
   실제 자료를 사용하면 원본의 출처와 표본 추출 단위를 기록합니다.
4. 양 끝 좌표를 자동차 그래프의 가장 가까운 노드에 스냅합니다.
   스냅 뒤에도 양 끝이 송파구 내부이고 서로 다른 노드인 통행을 후보로 남깁니다.
   스냅 거리 상한은 양 끝 각각 100m로 두고, 원좌표·스냅좌표·노드·스냅거리를 함께 저장합니다.
5. 후보 순서대로 두 수단의 경로를 확인하고 성공한 30건을 고정합니다.
   대중교통은 최소 한 번 차량에 타고 최대 세 번 탑승하며 최종 목적지까지 도달해야 합니다.
   접근·도착 도보는 각각 800m, 환승 도보는 500m 이내입니다.
   탈락 사유별 건수와 최종 30명 목록을 보관합니다.
   이 표본은 양쪽 수단으로 이동 가능한 사례이며 송파구 전체 수요의 대표 표본은 아닙니다.
6. 기준 날짜·09:00:00 출발·속도·거리 근사·파일 체크섬을 데이터 설명서에 기록합니다.
   준비한 자료와 노트북으로 외부 데이터 수집 없이 실행되는지 확인합니다.

GTFS 후보 원본은 저장소 `data/MANIFEST.toml`에 등록된 `GTFS_Korea_2024.zip`입니다.
DTUMOS의 로컬 원본에서 2024년 10월 7일 운행을 확인해 추출했습니다.
해당 원본에는 `calendar_dates.txt`가 없으며, `calendar.txt`의 유효기간과 요일로 운행을 골랐습니다.
하남시 자료의 지명만 송파구로 바꾸거나 검증하지 않은 결과를 싣지 않습니다.

## 제공 코드와 학생 빈칸

자료 변환·경로 복원·애니메이션까지 모두 학생에게 맡기면 예상 난이도를 넘습니다.
학생 빈칸은 알고리즘 호출, 단위 환산, 차이 계산, 집계와 시각화 연결로 제한합니다.

| 구분 | 강사가 제공할 부분 | 학생이 작성할 부분 |
|---|---|---|
| 준비 | 데이터 로더, 고정 O-D 30건, 입력 검증 | 자료 확인과 설명 |
| 택시 | 그래프, 경로 엣지 복원·거리 합산 | 다익스트라 호출과 분 환산 |
| 대중교통 | GTFS 변환, 접근·도착 후보, 경로 복원 | RAPTOR 호출과 총 시간 확인 |
| 비교 | 결과표 형식, 그래프 틀 | 차이·평균 계산과 해석 |
| 시각화 | 구간별 시각·좌표 변환, 공통 시계와 재생 틀 | 두 수단 결과 연결과 장면 해석 |

과제 안내와 실행 셀은 `assignment/assignment_2.ipynb` 하나에 모았습니다.
해당 노트북에는 데이터 로딩, O-D 지도, 한 사람의 경로 계산과 재생 예제가 들어 있습니다.
30명 반복 계산과 비교표·그래프·해석은 학생 작업으로 남겼습니다.

## 기존 코드 사용 시 확인할 부분

- `smartmob.teaching.dijkstra.dijkstra`는 결과 객체를 반환합니다.
  `labs/ch03_dijkstra.py`의 학생 함수는 튜플을 반환하므로 기본 과제에서는 참고 구현으로 통일합니다.
- `Path.distance_km(graph)`는 노드 사이 직선거리 합입니다.
  과제의 택시 거리는 선택된 엣지의 `length` 합을 사용하도록 별도 제공 함수를 준비합니다.
  평행 엣지가 있으면 탐색 비용과 일치하는 엣지를 선택하고, 시간 합도 반환값과 대조합니다.
- `smartmob.teaching.raptor.raptor`와 `journey`를 사용합니다.
  `labs/ch06_raptor.py`는 도착시각 배열만 반환하므로 이동 구간 복원에 그대로 쓰지 않습니다.
- RAPTOR의 목표는 마지막 정류장 도착이 아니라 도착 도보를 더한 목적지 도착입니다.
  복원 결과에 마지막 도보를 추가하고 대기시간까지 포함해 합산합니다.
- GTFS의 수단 코드가 표준 코드인지 자료 고유 코드인지 확인합니다.
  정류장 간 차내 거리는 근사값임을 결과표와 지도에 표시합니다.
- 애니메이션에는 탑승 구간 양 끝 시각만 쓰지 않습니다.
  선택 운행의 모든 경유 정류장 도착·출발시각을 유지하고 대기와 정차를 따로 표현합니다.
- 지도 좌표는 라이브러리가 요구하는 위경도 순서로 변환합니다.
  택시 엣지 형상과 대중교통 정류장 연결선을 같은 시계로 재생합니다.

## 배포 전 확인

30건 모두 양쪽 수단의 계산 성공 여부를 확인합니다.
시간 구성요소의 합, 택시 엣지 시간 합, 최종 도착시각과 애니메이션 종료를 대조합니다.
09:00·09:10·09:20의 도착 인원을 결과표와 화면에서 각각 확인합니다.
실행 노트북을 처음부터 실행하고, 학생 빈칸을 채운 검증본으로 예상 소요 시간을 확인합니다.
과제안의 미준비 안내를 데이터·기초코드 링크로 바꾸었습니다.
배포할 때는 `assignment/data/`, `assignment/assignment_2.ipynb`, `smartmob/`을 함께 제공합니다.
