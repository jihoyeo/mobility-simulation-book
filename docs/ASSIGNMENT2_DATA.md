# 과제 2 데이터: 송파구 통행 30건

도로망과 시간표는 실제 자료에서 추출했고, 출발지·목적지는 가상으로 생성했습니다.
실제 승객이나 택시 운행 기록은 포함하지 않습니다. 실행 예제는 [과제 노트북](../assignment/assignment_2.ipynb)에 있습니다.

## 학생에게 제공하는 파일

`assignment/data/`에는 두 파일만 있습니다.

| 파일 | 내용 |
| --- | --- |
| `od.csv` | 30명의 식별자, 원래 좌표, 스냅 좌표·노드, 스냅 거리, 날짜·출발시각 |
| `songpa_network.zip` | 도로망, GTFS 시간표, 송파구 경계, 출처·체크섬 |

ZIP을 직접 풀 필요는 없습니다. 노트북의 `load_data(DATA)`가 압축 파일을 읽습니다.
도로 노드 21,591개, 방향이 있는 엣지 57,103개, 노선 790개, 운행 39,692개, 정류장 11,945개가 들어 있습니다.

## 출처와 범위

- 도로: DTUMOS에 보관된 서울 OpenStreetMap 도로망 GeoPackage에서 추출했습니다. © OpenStreetMap contributors, [ODbL](https://www.openstreetmap.org/copyright). 원본 캐시에 수집일이 기록되어 있지 않아 시점은 알 수 없습니다. 날짜 대신 원본 SHA-256을 기록했습니다.
- 시간표: [CAMUS-LAB GTFS-2024](https://huggingface.co/datasets/CAMUS-LAB/GTFS-2024)의 `GTFS_Korea_2024.zip` 로컬 사본입니다. 저장소의 기존 데이터 목록에는 국토교통부 TAGO 기반·출처 표기 필요 자료로 등록되어 있습니다. 이 설명은 별도의 재배포 허가를 확인했다는 뜻은 아닙니다.
- 경계: [southkorea/seoul-maps의 KOSTAT 2013 경계](https://github.com/southkorea/seoul-maps/blob/master/kostat/2013/json/seoul_municipalities_geo.json)를 사용했습니다. 과제의 표본 범위를 정하는 기준이며, 현재 행정경계를 뜻하지 않습니다. 원 출처와 이용 조건은 해당 저장소를 참고합니다.

도로망은 송파구 경계에서 4km까지 넓힌 영역과 겹치는 서울 캐시의 자동차 도로입니다.
도로 엣지의 방향과 형상은 보존했습니다. 경기도 쪽 도로는 완전하지 않으므로 수도권 전체의 최단 경로를 보장하는 자료는 아닙니다.
자동차 도로 분류로 걸렀으며 별도 회전 제한과 혼잡은 적용하지 않습니다.

대중교통은 같은 영역 안의 정류장을 지나는 노선을 골랐습니다.
이 노선의 정류장 순서와 운행은 끝까지 보존해 경계에서 노선이 끊기지 않게 했습니다.
원본의 `route_type`은 이 데이터셋의 코드 체계를 따릅니다. 표준 GTFS 코드로 임의 변환하지 않았습니다.

## 날짜와 계산 조건

- 운행일: 2024년 10월 7일 월요일. `calendar.txt`의 기간과 요일을 확인해 운행을 골랐습니다. 원본에는 `calendar_dates.txt`가 없습니다.
- 모든 사람은 오전 9시에 출발합니다. 현재 교통 상황을 재현한 자료가 아닙니다.
- 택시 속도는 모든 도로에서 30km/h이며, 승차 대기는 0분입니다.
- 보행속도는 1.2m/s, 보행거리는 직선거리의 1.35배입니다. 실제 보행로 연결 여부는 확인하지 않습니다.
- 접근·도착 도보는 각각 800m 이하, 정류장 간 환승 도보는 500m 이하, 환승은 2회까지입니다.
- 택시 거리는 도로 엣지 길이의 합입니다. 대중교통 차내 거리는 경유 정류장 사이의 직선거리 합입니다.
- 도보시간은 초 단위로 올림합니다. 도보거리는 올림 전의 보정 거리이므로 거리/속도와 표시 시간이 약간 다를 수 있습니다.
- 두 수단 모두 스냅 좌표에서 출발·도착합니다. 원래 좌표와 스냅 좌표 사이의 이동은 제외합니다.

## 가상 O-D 생성

난수 시드 42로 송파구 경계 안에서 좌표를 뽑고 가장 가까운 자동차 도로 노드에 연결했습니다.
스냅 거리는 100m 이하이며, 옮긴 좌표도 경계 안에 있어야 합니다. 실제 표본의 최대 스냅 거리는 약 95.6m입니다.
원래 좌표와 옮긴 좌표를 모두 `od.csv`에 남겼습니다.

후보 31쌍 중 택시 경로가 없는 1쌍을 제외해 30쌍을 확정했습니다.
30쌍 모두 두 수단으로 목적지에 도착하고, 대중교통은 최소 한 번 차량에 탑승합니다.
이 과정에서 경로가 있는 통행만 골랐으므로 송파구 전체 수요를 대표하는 표본은 아닙니다.

## 재생성과 검증

저장소 루트에서 강사용 스크립트를 실행합니다. 추출은 원본 데이터가 있는 컴퓨터에서만 필요합니다. 중간 파일은 `outputs/assignment2_source/`에 둡니다.
새 환경에서는 위 경계 출처의 GeoJSON을 이 폴더에 `seoul_districts_2013.geojson`으로 먼저 저장합니다.

```powershell
$env:PYTHONPATH = "."
python tools/prepare_assignment2.py --source F:/research/DTUMOS/data
python tools/package_assignment2.py
python tools/build_assignment2_sample.py
```

마지막 명령은 O-D 생성과 30명 경로 검증을 함께 수행합니다.
참조 결과 CSV, 재생 HTML, 검증 기록은 `outputs/assignment2_instructor/`에 저장합니다.
교재의 알고리즘 구현을 사용하며 비공개 DTUMOS 코드를 복사하거나 import하지 않습니다.
