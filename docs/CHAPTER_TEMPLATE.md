## 같은 문단, 나쁘게 쓴 것과 잘 쓴 것

### 나쁜 예 (`chapter3.ipynb` §3.2.4 원문)

> 전처리 단계에서는 원시 데이터를 모델 학습에 적합한 형태로 변환한다. 이 과정에는 특성 스케일링, 범주형 변수의 인코딩, 결측치 처리 등이 포함된다. 또한 효율적이고 일관된 데이터 처리를 위해 전처리 파이프라인을 구축한다. 이 파이프라인은 향후 새로운 데이터에 대해서도 동일한 전처리를 적용할 수 있다.

### 좋은 예

> 지금 데이터에는 모델에 그대로 넣을 수 없는 컬럼이 둘 있습니다.
>
> 첫째는 `hour`입니다. `RIDE_DTIME`에서 뽑은 0~23의 정수인데, 모델은 이걸 "23시가 0시보다 23배 크다"고 읽습니다. 실제로는 23시와 0시가 붙어 있습니다. 시각을 원 위의 각도로 보고 `sin`, `cos` 두 값으로 바꾸면 이 문제가 없어집니다.
>
> 둘째는 `O_ADMDONG_CD`입니다. 행정동 코드는 종류가 많아서 그대로 원-핫 인코딩하면 열이 그만큼 늘어납니다. 통행이 100건 미만인 동은 하나로 묶습니다.
>
> 두 변환을 `ColumnTransformer`에 등록해 두면, 학습 데이터에 적용한 것과 똑같은 변환이 검증 데이터와 나중에 들어올 새 데이터에도 자동으로 적용됩니다. 파이프라인을 쓰는 이유가 이겁니다. 직접 변환하면 학습 때 만든 인코딩 표를 검증 때 잃어버리기 쉽습니다.

### 무엇을 바꿨나

| 바꾼 것 | 이유 |
|---|---|
| "특성 스케일링, 범주형 인코딩, 결측치 처리 등" → 이 데이터의 실제 컬럼 두 개 | 이식성 시험 통과. 다른 데이터에는 못 붙는 문장이 됐습니다 |
| "적합한 형태로 변환한다" → "23시가 0시보다 23배 크다고 읽습니다" | 무엇이 문제인지 학생이 머릿속에 그릴 수 있습니다 |
| "효율적이고 일관된 데이터 처리를 위해" 삭제 | 정보량 0 (L4) |
| 파이프라인을 쓰는 **이유**를 마지막에 추가 | 원문에는 "무엇"만 있고 "왜"가 없었습니다 |
| `hour`, `ColumnTransformer` 백틱 | S4 |

길이는 3배가 됐습니다. 그래도 이쪽이 낫습니다. 원문 4문장은 읽어도 아무것도 안 남으므로 사실상 0줄입니다.
