# 집필 스타일 가이드

이 책은 강의실 스크린에 띄워 놓고 말로 읽는 교재입니다. 판단 기준은 하나입니다. **화면에 띄운 문장을 소리 내어 읽었을 때 학생이 알아듣는가.**

벤치마크는 『밑바닥부터 시작하는 딥러닝』입니다. 벤치마킹하는 것은 종결어미가 아니라 세 가지입니다.

1. **장 첫머리는 대상과 용도를 밝힙니다.** 무엇을 배우고 어디에 쓰는지 설명한 뒤 구체적 사례로 이어집니다.
2. **설명한 뒤 실행합니다.** 본문에서 표·도식·손계산으로 원리를 익히고, 노트북에서 코드 결과와 대조합니다.
3. **수사가 없습니다.** 저자가 흥분하지 않습니다.

한 화면짜리 요약은 [STYLE-CHEATSHEET.md](STYLE-CHEATSHEET.md)에 있습니다. 작업 세션마다 첨부하는 것은 치트시트입니다.

## S0. 두 가지 판정 시험

문단을 쓰고 나서 다음 두 시험을 통과시킵니다. 이 가이드의 나머지 규칙은 대부분 이 두 시험의 각론입니다.

### 이식성 시험

이 문단을 이 책의 다른 장, 또는 아예 다른 분야의 교재에 그대로 붙여 넣어도 말이 되는가? 된다면 삭제합니다.

> 나쁜 예 (`chapter3.ipynb` §3.2.5): "모델 구축 단계에서는 ETA 예측을 위한 적절한 머신러닝 또는 딥러닝 모델을 선택하고 구현한다. 다양한 알고리즘을 비교하고, 모델의 구조와 하이퍼파라미터를 최적화하는 작업이 포함된다."

'ETA'만 다른 단어로 바꾸면 어떤 예측 문제에도 붙습니다. 삭제 대상입니다.

### 정보량 시험

문장에서 숫자, 고유명사, 코드 식별자, 파일명을 모두 지웠을 때 남는 게 있는가? 없으면 삭제합니다.

> 나쁜 예 (`chapter1.md` §1.4.1 끝): "이러한 어려움을 극복했을 때 얻을 수 있는 사회적 가치와 혁신의 잠재력은 충분히 도전할 만한 가치가 있다."

지울 것도 없습니다. 통째로 삭제합니다.

## S1. 문체

**본문 서술은 합니다체로 통일합니다.** 책 전체(`README.md`, `intro.md` 포함) 예외가 없습니다.

| 말의 종류 | 어미 | 예 |
|---|---|---|
| 서술 | `~합니다` / `~입니다` | "OSM의 엣지는 도로의 형상 좌표를 가집니다." |
| 독자에게 던지는 질문 | `~까요?` | "거리 컬럼이 없습니다. 어떻게 해결할까요?" |
| 같이 해 보자는 제안 | `~해 봅시다` | "시간대별 속도를 그려 보고 해석해 봅시다." |
| 과제 지시(연습문제 안) | `~해 봅시다` | "최단경로를 뽑아 지도에 그려 봅시다." |

**금지**: `~한다` / `~이다` / `~하자` / `~해라` / `~하세요`. 한 파일 안에서 섞이면 린터가 `KO001`로 잡습니다.

합니다체를 고른 이유는 『밑바닥부터 시작하는 딥러닝』 한국어판이 쓰는 문체이고, 학부 교재로 읽기에 부담이 적기 때문입니다. 현재 원고는 종결어미의 약 82%가 한다체이므로 수렴 비용이 있습니다. **재작성하는 장은 반드시 합니다체로 씁니다.**

저자의 개인적 의견이나 바람도 합니다체로 씁니다. 문체 때문에 사람 냄새를 없앨 필요는 없습니다.

> 좋은 예: "국내도 미국 주요 도시처럼 택시·스마트카드 데이터가 공개되기를 바랍니다."

## S2. 문장

**S2.1 길이.** 85자를 넘으면 경고, 120자를 넘으면 오류입니다. 한 문장에 절은 최대 2개.

**S2.2 관형격 `의`는 연속 2개까지.**

> 나쁜 예: "오픈소스 기반의 대규모 모빌리티 시뮬레이션 툴의 필요성이 대두된다."
> 고침: "도시 전체를 돌릴 수 있는 오픈소스 시뮬레이터가 필요합니다."

**S2.3 접속·수식 부사 금지 목록.** 아래 단어는 원칙적으로 쓰지 않습니다. 논리 접속이 정말 필요하면 `그런데` / `반면` / `대신` / `그래서`를 씁니다.

```
또한  더욱이  나아가  아울러  이를 통해  이러한 점에서  종합적으로
매우  굉장히  대단히  상당히  폭넓게  효과적으로  적극적으로
다양한  여러가지  각종  풍부한  심도 있는
```

`다양한`은 특히 위험합니다. 세어 보면 대부분 "몇 개인지 모르겠고 알아볼 생각도 없다"는 뜻입니다. 개수를 세서 쓰거나 뺍니다.

**S2.4 문단 첫 어절로 `이러한` / `이는` / `이를`을 연속해서 쓰지 않습니다.** 세 문단 연속이면 문단들이 서로를 가리키기만 하고 있다는 뜻입니다.

**S2.5 번역투.** `~되어진다`, `~에 있어서`, `~로 하여금`, `~을 가지고 있다`(→ `~입니다`/`~가 있습니다`), `~을 통해서`(→ `~로`).

## S3. LLM 문투 — 구체 패턴 13가지

각 항목은 (패턴 이름) / (현재 원고의 실물) / (고침) 형식입니다.

### L1. 형용사 삼단 나열

세 개짜리 병렬이 뜻 없이 리듬만 맞춥니다.

> "더 효율적이고, 지속 가능하며, 모든 이용자에게 공평한 모빌리티 시스템"

하나만 고르고 측정 가능하게 씁니다: "평균 대기시간이 짧은 시스템".

세 개 나열이 무조건 금지는 아닙니다. **세 항목이 각각 다른 정보를 담고 뒤에서 다시 쓰이면** 허용합니다.

### L2. "단순한 X가 아니라 Y이다"

> "시뮬레이션은 단순한 분석 도구가 아닌, 미래의 혁신적인 모빌리티 솔루션을 실험하고 검증할 수 있는 플랫폼이다."

X를 부정할 게 아니라 Y를 설명합니다: "시뮬레이터는 차량 대수를 바꿔 가며 같은 하루를 여러 번 돌려 보는 장치입니다."

### L3. 격상 어휘

다음은 이 책에서 **쓰지 않습니다**.

```
혁신적  패러다임(의 전환)  핵심 메시지  게임 체인저  무궁무진  획기적
필수적이다  시급하다  대두된다  부각시킨다  자리잡을 것이다  각광받는다
중추적  선도적  근본적인 변화  새로운 지평
```

`핵심적인`, `중요한`은 한 절에 1회까지. 무엇이 중요한지는 지면을 얼마나 썼는지로 이미 표시됩니다.

### L4. 빈 마무리 문장

문단 마지막 문장이 새 정보(숫자·이름·조건·반례)를 담지 않으면 삭제합니다.

> "이를 통해 우리는 더 효율적이고 … 한 걸음 더 다가갈 수 있을 것이다." → 삭제
> "실제 적용 시에는 데이터의 품질, 모델의 정확성, 윤리적 고려사항 등 다양한 요소를 종합적으로 고려해야 한다." → 삭제

### L5. 근거 없는 예측

`~할 것으로 예상됩니다`, `~이 될 전망입니다`, `이미 입증되었습니다`, `널리 알려져 있습니다`.

> "앞으로 Vehicle Relocation Algorithm은 스마트 시티와 미래 모빌리티 시스템의 핵심 요소로 자리잡을 것으로 예상된다."

인용을 달거나 삭제합니다. 예측을 꼭 쓰겠다면 주체를 밝힙니다: "Alonso-Mora 등(2017)은 뉴욕 택시 데이터에서 …라고 보고했습니다." (숫자는 원문 확인 후 기재)

### L6. 대칭 장단점 불릿

> ```
> - **장점**: 무료 사용 가능
> - **단점**: 복잡한 설정, 제한적 UI
> ```

장단점 대신 **"언제 쓰는가 / 무엇이 막히는가"**로 씁니다. 항목마다 사실이 하나 이상 들어가야 합니다(가격, 라이선스 이름, 지원 규모, API 유무).

### L7. 정의–입력–활용 3문장 템플릿의 반복

`chapter3.ipynb` §3.1.2에 이 형태가 12번 반복됩니다.

> "통행수요 예측은 특정 지역이나 노선의 미래 통행량을 예측하는 모델이다. 이 모델은 과거 통행 데이터, 인구통계, 경제지표, 날씨 등의 특성을 입력으로 사용한다. 예측 결과는 대중교통 노선 계획이나 도로 확장 계획 수립 등에 활용된다."

**하나만 골라 자세히 쓰고(입력 컬럼, 실제 대회/논문, 성능 수치), 나머지는 한 줄 목록으로 내립니다.** 12개를 다 설명하면 12개 다 안 읽힙니다.

### L8. 내용 없는 공정 서술

"데이터를 수집하고 정리합니다", "적절한 모델을 선택합니다", "필요한 경우 데이터를 결합합니다". 이식성 시험(S0)에 전부 걸립니다.

### L9. 주어 없는 당위

`~해야 합니다`, `~가 요구됩니다`, `~가 필요합니다`가 연속으로 나오면 누가 하는지 없다는 뜻입니다.

> "보안 정책을 수립하고 이를 엄격히 준수해야 한다." → 누가? 이 책의 독자가 할 일이 아니면 쓰지 않습니다.

### L10. 수사적 "우리"

"우리는 ~할 수 있을 것입니다"는 금지. **같이 코드를 따라가는 "우리"는 권장합니다.**

> 금지: "이를 통해 우리는 … 다가갈 수 있을 것입니다."
> 권장: "우리가 가진 데이터에는 거리 컬럼이 없습니다. 그래서 먼저 좌표로 거리를 만듭니다."

### L11. 볼드가 논증을 대신하는 것

S4를 참조합니다.

### L12. 절 중간에 튀어나오는 가짜 박스

`**핵심 메시지**:`, 절 안의 `**학습 목표**:`. 학습 목표는 장 머리에만 한 번 나옵니다.

### L13. 경구·선언·은유

짧은 문장으로 힘을 주는 경구, 반복으로 미는 강조, 개념을 대신하는 은유는 쓰지 않습니다. 한 번은 인상적이어도 책 전체에서 반복되면 문체가 되고, 소리 내어 읽으면 힘이 들어간 자리마다 흐름이 끊깁니다. 경구가 하려던 말을 조건이 담긴 평서문으로 폅니다.

> "돌아간다"와 "맞다"는 다릅니다. → 코드가 실행되는 것과 결과가 맞는 것은 별개입니다.
> 도시에는 되감기 버튼이 없습니다. → 실제 도시에서는 같은 기간을 조건만 바꿔 다시 관찰할 수 없습니다.
> 하나가 아니라 전부입니다. → (앞 문장이 이미 말했으므로) 삭제.
> 같은 저녁을 다시 살아야 합니다. → 같은 조건에서 다시 돌려 봐야 합니다.

`~일 뿐입니다`, `~의 전부입니다`, `그럴 리가 없습니다`, `고민할 것이 없습니다`처럼 단정으로 끝나는 짧은 문장이 문단 끝에 반복되면 이 패턴입니다. "밑바닥부터" 같은 다른 책의 브랜드 표현도 제목·본문에 쓰지 않습니다.

## S4. 강조 예산

| 수단 | 예산 | 용도 |
|---|---|---|
| `**볼드**` | 1,000자당 3개 이하 · 절당 문장 볼드 1개 · 최대 40자 | 처음 정의되는 용어(12자 이하), 또는 그 절의 핵심 주장 한 문장 |
| `<u>밑줄</u>` | **전면 금지** | HTML 전용이라 PDF 빌드에서 깨지고, 링크와 혼동됩니다 |
| `*이탤릭*` | 사용하지 않음 | 한글에서 안 읽힙니다 |
| `` `백틱` `` | 예산 없음 | 함수·컬럼·파일·패키지 이름은 **반드시** 백틱 |
| admonition | 절(`##`)당 1개 | `note`(옆길), `tip`(실습 요령), `warning`(자주 하는 실수) **3종만** |

`{important}`, `{caution}`, `{danger}`, `{attention}`, `{error}`, `{hint}`는 쓰지 않습니다. 종류가 많으면 색깔만 늘고 뜻은 안 늘어납니다.

볼드는 두 가지에만 씁니다.

1. **처음 정의되는 용어** — 12자 이하의 명사
2. **그 절의 핵심 주장 한 문장** — 절(`##`)당 하나까지, 40자 이하

문장 중간을 잘라 감싸지 않습니다. 볼드는 그 자체로 읽히는 단위여야 합니다.

> 나쁜 예: "**시뮬레이션을 통해 우리는 이러한 한계를 극복하고 다양한 시나리오를 안전하게 테스트**할 수 있다."
> 이유: 문장 중간이 잘렸고, 40자를 넘고, 한 문단에 이런 것이 여럿입니다.

원래 원고가 무너진 지점은 볼드의 길이가 아니라 **밀도**였습니다. 1장은 1,000자당 7.2개를 썼습니다. 이 예산을 지키면 강조가 다시 강조로 읽힙니다.

## S5. 개념을 도입하는 순서

### 장 첫머리

첫 문단은 장에서 다루는 대상의 정의와 용도를 밝힙니다. 이어서 실제 활용처와 이 장의 학습 범위를 설명합니다.
GTFS라면 공개 데이터 표준이라는 정의, Google 지도 등의 활용, 파일 구성을 먼저 읽습니다.
파일별 정보·대표 필드·식별자 관계를 확인한 뒤 작은 시간표와 실습으로 넘어갑니다.
아직 대상이 무엇인지 설명하지 않은 채 가상의 승객이나 특정 시각 질문으로 장을 시작하지 않습니다.

### 절 안에서 개념을 설명하기

1. **구체적 질문.** 배울 대상의 용도를 이해한 뒤, 작은 예제에서 답할 질문을 제시합니다.
2. **표·도식과 손계산.** 각 값의 뜻과 계산 순서를 설명합니다. 정류장 세 곳이나 출발편 두 개처럼 손으로 확인할 규모를 씁니다.
3. **결과 예상.** 코드를 실행하기 전에 학생이 어느 행을 읽고 어떤 값을 얻을지 적습니다.
4. **실행과 대조.** 노트북에서 5~15줄 정도의 코드를 실행하고 예상과 비교합니다. 셀 아래에 출력을 읽는 문장을 붙입니다.
5. **조건 변경.** 출발시각이나 배차간격을 하나 바꾸고, 결과가 달라지는 이유를 설명합니다.

본문은 원리·구성·해석을 중심으로 쓰고 실행 코드는 실습 노트북에 둡니다.
자료 변환, 알고리즘 구현, 대규모 분석을 한꺼번에 요구하지 않습니다. 추가 탐색과 통합 과제는 별도로 안내합니다.
수업 회차·시간 배분·수업 종료 같은 운영 안내는 본문과 노트북에 넣지 않습니다. 개념의 연결과 필요한 선행 설명으로 학습 순서를 드러냅니다.

## S7. 그림·표·코드·연습문제

강의 본문은 일반 Markdown 프리뷰에서 읽을 수 있어야 합니다. 실행 코드와 사용법은 별도 실습 노트북에 둡니다. 본문에는 수식·저장된 그림·결과표와 해석을 사용하며, 코드 실행을 강의의 전제로 삼지 않습니다. Jupytext·kernelspec 메타데이터, MyST 전용 지시문·역할, raw HTML을 본문에 추가하지 않습니다. 참고 사항은 인용문, 연습문제는 소제목, 실습 연결은 표준 링크로 씁니다. 계산 결과의 입력 조건과 출처를 확인하고, 변경한 이미지·링크 경로와 프리뷰를 점검합니다.

### 그림

- 일반 Markdown 이미지 문법 `![설명](../figures/파일.svg)`을 사용합니다. 캡션은 그림 아래 일반 문단에 쓰고, 본문에서 그림의 의미를 설명합니다. MyST 전용 그림 지시문과 옵션은 사용하지 않습니다.
- `<div style=...>`, `<p style="text-align:center">` 같은 raw HTML 캡션·레이아웃은 전부 제거합니다. 그림 두 장은 표준 Markdown 이미지 두 개로 나눕니다. iframe은 별도 HTML을 여는 Markdown 링크로 바꿉니다.
- **본문에서 한 번도 참조하지 않는 그림은 삭제합니다.** "그림 1.3에서 보듯…" 문장이 없으면 그 그림은 장식입니다.
- 캡션은 무엇을 보라는 지시여야 합니다. `[VISSIM 시뮬레이션 화면]`(X) → `VISSIM의 미시 시뮬레이션 화면. 차량마다 차로 위 위치가 개별로 그려집니다.`(O)

### 표

- 3열 이상 **그리고** 4행 이상일 때만 표를 씁니다. 그보다 작으면 문장으로 씁니다.
- 모든 칸에 사실(숫자·이름·조건)이 있어야 합니다. 빈 칸이나 `-`가 절반을 넘으면 표가 아닙니다.
- `장점 / 단점` 열은 만들지 않습니다(L6).

### 실습 노트북의 코드 셀

- 셀 하나 = 개념 하나. 20줄을 넘으면 나눕니다.
- 셀 **위** 마크다운: 무엇을 왜 하는지 1~3문장.
- 셀 **아래** 마크다운: 출력이 있으면 반드시 해석 1~2문장. 출력만 있고 해석이 없는 셀은 미완성입니다.
- 코드 안 주석은 한국어, 한 줄, 왜(why)만. 무엇(what)은 코드가 이미 말합니다.
