## 여는 법

저장소 뿌리에서 주피터를 띄우고 `labs/` 로 들어갑니다.

```bash
jupyter lab
```

노트북은 위에서부터 순서대로 실행합니다. 첫 셀이 경로를 잡아 주므로 `labs/` 밖에서 열어도 됩니다.

서버 없이도 전부 돌아갑니다. DTUMOS 에 연결하지 못하면 `data/fixtures/` 의 녹화본을 씁니다.

## 빈칸

노트북 안의 빈칸은 `None` 으로 비어 있습니다. 채우고 그 아래 셀을 실행하면 맞는지 알려 줍니다.

```python
peak_minute = None      # 여기를 채웁니다
todo("가장 붐빈 시각", peak_minute)
```

```
[ ] 가장 붐빈 시각 — 아직 채우지 않았습니다
```

채우지 않아도 노트북은 끝까지 돌아갑니다. 처음 열었을 때 오류가 나지 않게 하려는 것입니다.

## 채점받는 셋

3장, 6장, 11장은 노트북이 아니라 **옆의 `.py` 파일** 을 채웁니다.

노트북에서 `%autoreload` 를 켜 두었으므로, 편집기에서 파일을 고치고 저장한 뒤
노트북 셀을 다시 실행하면 바로 반영됩니다. 커널을 다시 시작하지 않아도 됩니다.

파일을 나눈 이유가 있습니다. 채점기와 `tests/` 가 그 파일을 직접 불러다 씁니다.
노트북은 셀을 어떤 순서로 실행했는지에 따라 결과가 달라지지만, 파일은 그렇지 않습니다.

각 함수의 docstring 에 해야 할 일과 막히기 쉬운 지점이 적혀 있습니다.
파일을 그냥 실행해도 됩니다.

```bash
python labs/ch03_dijkstra.py
```

## 자가 채점

```bash
python labs/check.py ch03      # 하나씩
python labs/check.py all       # 전부
```

노트북 안에서는 이렇게 부릅니다.

```python
from check import check
check("ch03")
```

`check.py` 가 보는 것은 `tests/` 가 보는 것과 같습니다. **여기를 통과하면 과제 채점도 통과합니다.**

기준을 미리 알려 주는 이유가 있습니다. 이 과목에서 배우는 것 중 하나가 "돌아간다"와 "맞다"를 구분하는 습관입니다.
무엇과 대조해야 맞는 것인지를 아는 것이 그 절반입니다.

| 실습 | 무엇과 대조하는가 |
|---|---|
| 3장 | NetworkX 의 최단거리와 30쌍 완전 일치 |
| 6장 | 답을 손으로 아는 작은 시간표 5케이스 + 실제 하남 GTFS 불변식 2개 |
| 11장 | DTUMOS 엔진과 평균 대기시간 1.5분 이내, 출력 형식 일치 |

## 12장 웹 뷰어

이 책에서 파이썬이 아닌 코드를 채우는 유일한 자리입니다.

`ch12_viewer/` 는 DTUMOS 화면의 핵심만 남긴 것입니다. DTUMOS 는 React 와 deck.gl 로
통행 컴포넌트 하나가 1,800줄이 넘지만, 차가 움직이는 것을 보여 주는 부분은 셋뿐입니다.
좌표열과 시각열을 레이어에 전달하고, 매 프레임 시각을 조금 늘리고, 다시 그립니다.

DTUMOS 와 같은 방식으로 실행하되 가볍게 유지했습니다.
의존성은 deck.gl 세 개와 Vite 하나뿐이고, React 도 상태 관리 라이브러리도 없습니다.
학생이 고치는 파일은 `src/main.js` 하나이고, 그 안의 다섯 자리가 빈칸입니다.

먼저 `ch12_metrics.ipynb` 에서 데이터를 내보냅니다.

```python
from smartmob.viz import export_viewer
export_viewer(engine, "ch12_viewer/public/data", sample=200)
```

그다음 실행합니다. Node 20.19 이상이 필요합니다.

```bash
cd labs/ch12_viewer
npm install        # 처음 한 번만
npm run dev        # npm start 도 같습니다
```

브라우저가 자동으로 열립니다. 처음에는 지도만 나오고 왼쪽에 남은 빈칸이 뜹니다.
`src/main.js` 를 고치고 저장하면 브라우저가 알아서 다시 그립니다.

채점은 저장소 뿌리에서 합니다.

```bash
node tools/check_viewer.mjs
```

내보낸 파일의 이름과 키는 DTUMOS 가 내는 것 그대로입니다.
서버에서 받은 결과 디렉터리를 `public/data/` 에 그대로 복사해도 돌아갑니다.
11장에서 직접 짠 루프의 결과도 같은 함수로 내보낼 수 있습니다.

자세한 것은 [`ch12_viewer/README.md`](ch12_viewer/README.md) 에 있습니다.
