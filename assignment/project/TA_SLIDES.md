# 가상 셔틀 시뮬레이션 실습

조교용 교안 · 반도체대학 ↔ AI공학관 가상 직통 노선

구분선마다 슬라이드 한 장으로 사용함
설치와 실행 방법은 [예제 실행 안내](mudang-sim/README.md)를 참고함

---

## 1. 예제와 실행

### 01. 두 정류장만 있는 셔틀

- 반도체대학 → AI공학관 → 반도체대학으로 돌아오는 가상 노선임
  - 실제 무당이와 장소 이름만 같음
  - 시간표, 도로, 차량 정원과 승객 수는 실습용으로 정한 값임
- 편도 5분, AI공학관에서 30초 정차함
  - 한 바퀴에 5분 + 30초 + 5분 = 10분 30초가 걸림
- 차량 수와 정원을 바꾸며 기다리는 사람이 어떻게 달라지는지 확인함
  - 실제 무당이 자료와 모형은 이 예제를 익힌 뒤 직접 구축함

---

### 02. 프로그램 실행

- Node.js 설치 후 `mudang-sim` 폴더에서 터미널을 실행함
  - `package.json` 파일이 보이는 폴더인지 확인함
- 다음 순서로 실행함
  - `npm install`: 실행에 필요한 패키지 설치
  - `npm run gtfs`: 예제 시간표 생성 / `npm run dev`: 웹 화면 실행
- 터미널에 표시된 주소를 브라우저로 엶
  - 처음에는 설정을 바꾸지 않고 재생 버튼을 누름
  - 차량이 움직이고 정류장 대기인원이 바뀌는지 확인함

---

## 2. GTFS: 어디에 언제 서는가

### 03. GTFS는 운행 정보를 담은 표 묶음

- 정류장 표에는 정류장 이름과 위치를 저장함
  - 예제에는 반도체대학과 AI공학관 두 곳만 있음
- 노선 표에는 어떤 노선인지를, 운행편 표에는 개별 운행을 저장함
  - 같은 노선의 11:00 출발편과 11:10 출발편은 서로 다른 운행편임
- 정차 시간표에는 각 편이 어느 정류장에 언제 서는지 저장함
  - 운행일을 정하는 표와 운영기관을 적는 표도 함께 사용함

---

### 04. 파일 이름과 내용 연결

- `stops.txt`: 정류장 / `routes.txt`: 노선
  - 정류장과 노선에 ID를 붙여 다른 표에서 같은 대상을 가리킴
- `trips.txt`: 운행편 / `stop_times.txt`: 정류장별 도착·출발 시각
  - 운행편 ID로 두 표를 연결함
- `calendar.txt`, `calendar_dates.txt`: 운행일과 예외일
  - `agency.txt`에는 운영기관과 시간대를 기록함
  - 필드의 자세한 의미는 [GTFS 명세](https://gtfs.org/documentation/schedule/reference/)를 참고함

---

### 05. 첫 운행편의 시간표

- 반도체대학에서 11:00에 출발함
  - AI공학관에 11:05 도착 → 30초 정차 → 11:05:30 출발
  - 반도체대학에 11:10:30 도착
- 같은 반도체대학이 시간표에 두 번 나옴
  - 첫 번째는 출발, 두 번째는 돌아온 시점임
  - 같은 정류장 ID를 쓰되 방문 순서는 따로 기록함
- 예제는 11:00부터 10분 간격으로 6개 편을 생성함
  - 6개 운행편이 있다고 차량도 6대 필요한 것은 아님
  - 돌아온 차량을 다음 편에 다시 투입할 수 있음

---

## 3. 도로 경로와 이동시간

### 06. 시간표와 도로망의 역할

- 시간표에서 반도체대학 다음 정류장이 AI공학관임을 확인함
  - 어느 도로를 지나가는지는 별도로 정해야 함
- 도로망은 교차점과 그 사이의 도로를 연결한 자료임
  - 교차점은 ‘노드’, 연결된 도로는 ‘링크’라고 부름
  - 예제에서는 두 정류장을 건물 인근의 도로 노드에 연결함
- 실제 과제에서는 셔틀이 지나갈 수 있는 도로를 직접 확인함
  - 보행로와 차량 진입 제한 구간을 구분함

---

### 07. 지도 위에서 도로를 따라 이동

- 예제에 저장된 교내 OSM 도로망으로 경로를 계산함
  - 두 예시 정차점 사이 최단거리는 편도 약 995m임
  - 다익스트라로 도로 거리의 합이 가장 작은 길을 찾음
- 차량은 도로가 굽어지는 지점을 차례로 따라감
  - 지도에서 확대·이동하며 경로와 차량 위치를 확인함
  - 정류장 옆 숫자는 대기인원, 차량 안 숫자는 탑승인원임
- 실제 도로 위에 가상의 운행을 올린 예제임
  - 정차점·시간표·수요는 예시이며 실제 운행 자료는 직접 구축함
  - 실제 셔틀의 통행 가능 여부와 운행 경로는 현장 확인이 필요함

---

### 08. 경로를 정해도 걸리는 시간은 따로 필요함

- 경로는 ‘어느 길로 가는가’를 정함
  - 이동시간 모형은 ‘그 길을 몇 분 만에 가는가’를 정함
- 이 예제의 ETA는 구간 이동시간을 계산하는 모형임
  - 지금은 GTFS에 적힌 편도 5분을 그대로 사용함
  - 도로 거리를 바꿔도 시간표가 같으면 이동시간은 여전히 5분임
- 학생은 관측 자료로 이동시간 모형을 교체함
  - 시간대에 따라 더 오래 걸리는지, 정차시간은 얼마인지 확인함
  - 주행시간과 정차시간을 구분해 같은 시간을 두 번 더하지 않도록 함

---

### 09. 이번 예제에는 RAPTOR가 필요하지 않음

- 승객은 두 정류장 사이에서 한 노선만 이용함
  - 다른 노선이나 환승 방법을 고를 필요가 없음
- 승객이 언제 타는지는 차량 도착과 빈자리로 결정함
  - 자리가 있으면 탑승, 만차이면 다음 차량까지 기다림
- 도로 경로 계산과 승객의 환승 경로 계산은 구분함
  - 다익스트라: 차량이 지나갈 도로 경로 계산
  - RAPTOR: 여러 노선의 시간표에서 승객의 이동 경로 탐색

---

## 4. 승객 도착과 승하차

### 10. 승객 한 명을 어떻게 표현하는가

- 승객에게 세 가지 정보를 부여함
  - 정류장 도착 시각 / 타는 곳 / 내리는 곳
- 예: 11:02에 반도체대학에 도착해 AI공학관으로 가려는 승객
  - 11:02부터 반도체대학 대기열에 들어감
  - 아직 차량에 타지 않았으므로 탑승 시각은 정해지지 않음
- 예제는 이런 가상 승객 180명을 생성함
  - 같은 조건에서 비교할 수 있도록 생성 규칙과 난수 시드를 고정함
  - 실제 무당이 이용자 수를 추정한 값은 아님

---

### 11. 차량이 도착했을 때의 처리 순서

- 먼저 목적지에 도착한 승객을 내림
  - 내린 뒤 차 안에 몇 명이 남았는지 확인함
- 빈자리만큼 대기열 앞에서부터 태움
  - 먼저 도착한 승객이 먼저 타는 방식임
- 못 탄 승객은 대기열에 그대로 남음
  - 다음 차량에서 다시 탑승을 시도함
  - 처음 정류장에 도착한 시각을 지우지 않아야 전체 대기시간을 알 수 있음

---

### 12. 정원 제한 계산 예시

- 정원 5명인 차량에 4명이 타고 있다고 가정함
  - 이번 정류장에서 2명이 내리면 차내 인원은 2명임
  - 빈자리는 5 − 2 = 3자리임
- 정류장에는 5명이 기다리고 있음
  - 먼저 온 3명이 탑승함
  - 탑승 후 차내 인원은 5명, 남은 대기인원은 2명임
- 남은 2명은 다음 차량을 기다림
  - 차량이 정류장에 왔더라도 못 탔다면 대기는 끝나지 않음

---

### 13. 차량 한 대로 10분 간격을 지킬 수 있는가

- 예제의 한 바퀴 소요시간은 10분 30초임
  - 11:00에 출발한 차량은 11:10:30에 돌아옴
- 차량이 한 대라면 11:10 예정편은 출발할 수 없음
  - 차량이 돌아온 뒤인 11:10:30에 출발함
  - 이 예제는 돌아오면 바로 다음 편에 투입할 수 있다고 가정함
- 차량이 두 대라면 두 번째 차량이 11:10에 출발할 수 있음
  - 시간표를 촘촘하게 만드는 것과 차량을 실제로 운행하는 것은 별도로 확인해야 함

---

### 14. 대기시간 계산 예시

- 승객이 11:02에 도착해 11:10에 탑승했다고 가정함
  - 대기시간은 11:10 − 11:02 = 8분임
- 11:15에 목적지에서 내렸다면 차량 안에서 보낸 시간은 5분임
  - 정류장 도착부터 하차까지 걸린 시간은 8분 + 5분 = 13분임
- 만차로 11:10 차량을 못 탔다면 탑승 시각은 아직 정해지지 않음
  - 실제로 탈 때까지 계속 기다린 것으로 계산함
  - 버스 도착 시각을 승객의 탑승 시각으로 대신 쓰면 안 됨

---

### 15. 실험이 끝났을 때 인원 확인

- 12:00에 계산을 멈추면 승객은 세 상태로 나뉨
  - 목적지 도착 완료 / 아직 차 안에 있음 / 아직 정류장에서 기다림
- 세 상태의 인원을 더하면 총수요와 같아야 함
  - 맞지 않으면 승객을 중복 집계하거나 빠뜨렸는지 확인함
- 아직 못 탄 승객의 대기시간은 끝나지 않은 값임
  - 현재까지 기다린 시간만 따로 표시함
  - 이미 탑승한 승객의 평균 대기와 섞지 않음

---

## 5. 운행 재생과 조건 변경

### 16. 화면의 숫자 읽기

- 왼쪽 입력창에서 바꿀 조건을 정함
  - 차량 수 / 배차간격 / 정원
- 재생 화면은 시간에 따른 차량과 승객 상태를 보여 줌
  - 정류장 옆 숫자는 대기인원, 차량의 숫자는 차내 인원임
- 지도 아래 인원은 현재 재생 시각의 상태임
  - 재생 막대를 움직이면 대기·탑승·하차 인원도 바뀜
  - 재생은 이미 계산한 기록을 다시 보여 주는 기능임

---

### 17. 조건 하나씩 바꾸어 비교

- 처음에는 기본 설정으로 차량 이동과 승하차를 확인함
  - 기본값: 차량 2대 / 정원 20명 / 10분 간격
- 차량만 1대로 줄여 다시 실행함
  - 출발 지연, 정류장 대기인원과 미탑승 인원을 확인함
- 기본값으로 되돌린 뒤 정원이나 배차간격을 따로 바꿈
  - 한 번에 여러 조건을 바꾸면 무엇 때문에 결과가 달라졌는지 구분하기 어려움
  - 설정을 바꿔도 같은 승객 목록을 사용함

---

### 18. 평균 대기만 보면 놓치는 것

- 계산 결과의 평균 대기는 실제로 탑승한 승객만의 평균임
  - 오래 기다렸지만 아직 못 탄 승객은 평균에서 빠져 있음
- 평균이 줄었더라도 미탑승 인원이 늘었다면 개선으로 단정하지 않음
  - 도착 완료 인원과 미탑승 인원을 함께 비교함
  - 미탑승자가 현재까지 얼마나 기다렸는지도 확인함
- 차량 출발도 예정편 수와 실제 출발편 수를 나누어 봄
  - 출발 지연 평균에 아직 출발하지 못한 편은 포함되지 않음

---

### 19. 결과 파일과 대시보드 연결

- 결과 저장과 비교 화면은 학생이 추가할 기능임
  - 입력 조건, 승객 목록, 도로 경로와 승하차 기록을 함께 저장하도록 구현함
- 계산과 화면은 파일을 나누어 구성함
  - `simulation.js`: 승객·차량 상태 계산
  - `main.js`: 계산 결과를 화면에 표시
- 학생의 보고서와 대시보드는 같은 계산 결과를 사용하도록 구성함
  - 결과 파일의 시간은 초 단위이므로 화면의 분 단위 값과 환산해 비교함

---

## 6. 학생이 개발할 부분

### 20. 가상 자료를 실제 자료로 교체

- 실제 GTFS와 교내 도로망을 구축함
  - 정류장 위치, 상·하행 순서, 운행일과 시간표를 확인함
  - 차량이 통행할 수 있는 도로와 정류장을 연결함
- 조사 자료로 ETA와 수요 모형을 구축함
  - 시간대별 이동시간, 승객 도착량과 출발지·목적지를 추정함
  - 관측한 값과 가정한 값을 구분함
- 예제의 숫자만 바꾼 결과를 실제 무당이 분석으로 사용하지 않음
  - 실제 조사 자료와 결과가 얼마나 맞는지 먼저 확인함

---

### 21. 실제 자료로 확인할 항목

- 차량 기록은 실제 운행 자료와 비교함
  - 정류장 방문 순서, 구간 이동시간과 출발 간격을 확인함
- 승객 기록은 같은 시간대의 관찰 자료와 비교함
  - 대기인원, 승하차 인원과 직접 기다린 시간을 확인함
- 차이가 나면 원인을 하나씩 살펴봄
  - 수요가 다른지, 이동시간이 다른지, 승하차 규칙이 다른지 확인함
  - 관찰하지 않은 시간대는 수요 0명이나 검증 완료 구간으로 취급하지 않음

---

### 22. 예제에 없는 조건과 최종 과제

- 예제는 모든 차량이 반도체대학에서 출발한다고 가정함
  - 교통 혼잡, 충전, 운휴와 운전자 휴식은 구현하지 않음
- 승객 수와 관계없이 정차시간을 고정함
