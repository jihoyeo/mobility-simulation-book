# 가상 직통 셔틀 시뮬레이션

반도체대학과 AI공학관 두 정류장만 오가는 가상의 직통 노선입니다.
OSM의 실제 교내 도로 위에 가상의 노선·시간표·수요를 적용합니다. 정차점은 건물 인근 도로의 예시 위치입니다.
학생은 실행 구조를 익힌 뒤 실제 GTFS, 도로망, ETA, 수요 모형을 직접 구축합니다.

이 폴더만 복사해 실행할 수 있습니다. Python, 지도 API 키, 별도 서버는 필요하지 않습니다.

## 실행

[Node.js 공식 사이트](https://nodejs.org/en/download)에서 Node.js 24 LTS를 설치합니다.
이 폴더의 `package.json`이 있는 위치에서 터미널을 열고 다음 명령을 실행합니다.

```sh
npm install
npm run dev
```

터미널에 표시되는 주소를 브라우저로 엽니다. 기본 주소는 `http://127.0.0.1:5173`입니다.
`npm run vite`로도 실행할 수 있습니다. 종료할 때는 터미널에서 `Ctrl+C`를 누릅니다.
포트를 사용 중이면 Vite가 표시하는 다른 주소로 접속합니다.
Node.js 설치 직후에는 터미널을 다시 열고 `node --version`, `npm --version`으로 확인합니다.

## 1. GTFS 생성

```sh
npm run gtfs
```

`scripts/make-demo-gtfs.mjs`가 `demo-gtfs/`의 가상 시간표를 생성합니다.
이 명령은 예제 파일을 덮어쓰므로 학생이 만든 피드는 별도로 보관합니다.
생성한 파일도 함께 제공하므로 첫 실행 때 이 명령을 생략해도 됩니다.

| 파일 | 예제 내용 | 학생이 구축할 내용 |
|---|---|---|
| `agency.txt` | 가상 운영기관 | 운영기관과 시간대 |
| `stops.txt` | 이름 두 개와 예시 좌표 | 실제 정류장 ID와 측정·확인한 좌표 |
| `routes.txt` | 가상의 직통 노선 하나 | 실제 운행 노선 |
| `trips.txt` | 10분 간격의 6개 운행편 | 운행일별 실제 운행편 |
| `stop_times.txt` | 반도체대학 → AI공학관 → 반도체대학 | 정류장 순서·도착·출발 시각 |
| `calendar.txt`, `calendar_dates.txt` | 2026년 평일 운행 | 실제 운행일과 예외일 |

예제 운행일은 2026-11-02이며, 11:00부터 12:00까지 한 시간만 계산합니다.
각 구간은 5분, AI공학관 정차는 30초입니다. 한 바퀴 10분 30초는 이 가정으로 계산한 값입니다.
실제 무당이의 소요시간이나 배차간격을 뜻하지 않습니다.

`src/gtfs.js`는 정류장 방문 순서와 시간표를 읽습니다.
동일한 정차 패턴·구간시간을 가진 순환 운행편만 지원하며, 모든 GTFS를 처리하는 라이브러리는 아닙니다.
운행 달력과 예외일, 24시를 넘는 시각을 처리합니다. 운행일은 `readFeed()`의 기본값으로 지정합니다.
출발·도착의 반도체대학은 같은 정류장이지만 방문 순서는 각각 0번과 2번입니다.
[GTFS 명세](https://gtfs.org/documentation/schedule/reference/)에서 각 파일의 의미를 확인할 수 있습니다.

## 2. 차량 출발과 승하차

`src/simulation.js`는 1초마다 승객 도착, 차량 도착, 하차, 승차, 예정편 출발을 처리합니다.
먼저 온 승객부터 빈자리만큼 태웁니다. 만차이면 다음 차량까지 대기열에 남습니다.
동일한 초에 도착한 승객은 그 시각의 차량에 탈 수 있습니다.
AI공학관에서는 도착 시점에 한 번 승차하며, 정차 중 늦게 온 승객은 다음 편을 기다립니다.
반도체대학에서는 예정 출발 시각에 승차합니다.

차량은 반도체대학에 돌아온 뒤에만 다음 운행편에 투입됩니다.
가용 차량이 없으면 예정편이 지연됩니다. 지연된 예정편은 순서대로 출발합니다.
이 예제의 배차는 최적화 알고리즘이 아닌 시간표 기반 출발과 선착순 승차입니다.

대기시간은 실제 탑승 시각에서 정류장 도착 시각을 뺀 값입니다.
평균·90백분위 대기시간은 탑승한 승객만의 값이며, 미탑승자의 경과 대기도 별도로 표시합니다.
종료 시 도착 완료·차내·미탑승의 합은 총 수요와 같습니다.
종료 시각의 하차는 반영하지만 새로운 승차·출발은 처리하지 않습니다.
아직 출발하지 못한 편은 출발 지연 평균에 포함되지 않으므로 해당 편수도 함께 확인합니다.

## 3. 도로 경로 계산

GTFS에는 도로망 연결 관계가 없습니다. `src/network.js`가 별도의 OSM 도로망과 정류장–노드 연결을 제공합니다.
`campus-roads.json`에 가천대학교 주변 도로를 저장해 별도 라우팅 서버 없이 실행합니다.
다익스트라로 왕복 경로를 각각 계산하며, 현재 예시 정차점 사이 거리는 편도 약 995m입니다.
도로 굴곡을 구성하는 모든 노드를 유지하고, 차량은 누적 거리에 따라 위경도를 보간해 이동합니다.
`src/map.js`는 MapLibre 지도로 도로·정류장·차량을 표시합니다. 재생 속도는 약 20배입니다.

도로와 건물은 실제 지리 자료이며, 정차점은 건물 근처 도로 위에 잡은 예시 위치입니다.
실제 승강장·무당이 운행 경로·차량 통행 가능 여부를 검증한 자료는 아닙니다.
노선·시간표·수요는 계속 가상이며, 실제 운영 자료 구축은 학생 과제입니다.

배경 타일에는 인터넷 연결이 필요합니다. 연결이 끊겨도 저장된 도로·건물과 차량은 표시됩니다.
도로·건물 자료의 출처와 재구축 방법은 [데이터 출처](DATA_SOURCES.md)에 정리했습니다.

이 단계는 차량의 도로 경로 계산입니다. 승객의 환승 경로를 찾는 RAPTOR와는 역할이 다릅니다.
단일 직통 노선에서 RAPTOR는 필수가 아닙니다.
실제 과제에서는 학생이 교내 도로망을 구축하고 정류장을 연결합니다.
최단거리 경로가 실제 셔틀이 통행할 수 있는 길인지 일방통행·진입 제한·노선 제약을 검토합니다.

## 4. ETA와 수요

`src/models.js`의 `timetableETA()`와 `exampleDemand()`를 교체합니다.
기본 ETA는 GTFS 시각의 차이인 편도 5분을 사용합니다. 도로 거리로 ETA를 추정하는 모형은 아직 없습니다.
화면의 차량은 주어진 구간시간 동안 경로의 거리에 비례해 이동합니다.
학생은 도로 경로·관측 자료를 이용해 구간·시간대별 ETA를 추정합니다.
ETA 함수는 구간 번호와 출발 시각을 받아 양의 정수 초를 반환합니다.
시각은 실험 시작부터 경과한 초이며, 시간대 모형에는 GTFS의 시작 시각을 더합니다.
정차·대기시간은 ETA에 다시 더하지 않습니다.

기본 수요는 가상 승객 180명입니다. 한 시간 안의 도착 시각과 방향을 고정 시드 42로 생성합니다.
반도체대학 출발 비중은 모형에서 80%로 설정했으며 실제 비중이 아닙니다.
승객 한 명은 `id`, `arrival`, `origin`, `destination`으로 구성됩니다.
`arrival`은 경과 초이며, `origin`과 `destination`은 GTFS 방문 순서의 0부터 시작하는 번호입니다.
관찰 자료만으로 하루 전체 수요나 완전한 OD를 관측했다고 가정하지 않습니다.

## 5. 운행 재생

화면에서는 차량 수, 배차간격, 정원을 설정합니다.
‘설정 적용’을 누른 뒤 ‘재생’을 누르면 지도 위에서 차량이 이동합니다.
편도 이동시간은 5분, 수요는 시간당 180명으로 고정합니다.
지도 아래의 정류장 도착 누계·대기 중·탑승 중·하차 완료 인원은 재생 시각에 맞춰 바뀝니다.

1. 기본값으로 재생해 차량 이동과 승하차를 확인합니다.
2. 차량을 1대로 줄여 차량이 돌아올 때까지 다음 출발이 지연되는지 확인합니다.
3. 정원을 줄여 못 탄 승객이 다음 편까지 기다리는지 확인합니다.
4. 같은 시각에서 대기인원을 비교합니다. 매 실행에는 같은 예제 승객을 사용합니다.

시나리오 비교표·그래프·결과 파일 저장은 학생이 추가할 기능입니다.
`simulation.js`의 반환값에는 승객별 시각, 승하차 기록과 요약 지표가 포함됩니다.

실제 GTFS·도로망 구축, ETA·수요 모형, 검증과 최종 대시보드는 학생 과제로 남깁니다.
교통 혼잡·충전·운휴·승객 포기·환승·보행·승하차 인원에 따른 정차시간 변화는 구현하지 않았습니다.

## 검사와 빌드

```sh
npm test
npm run build
```

검사는 정원 제한, 차량 중복 투입, 종료 시점 인원 보존, GTFS와 최단경로를 확인합니다.
빌드는 `dist/`에 정적 웹 파일을 만듭니다. `node_modules/`와 `dist/`는 제출하지 않습니다.
