# 실습 과제

교재에서 직접 짜기로 한 세 가지의 빈칸판입니다.

| 파일 | 교재 | 주차 | 분량 |
|---|---|---|---|
| `w03_dijkstra.py` | 3장 | 3주차 | 약 90줄 |
| `w06_raptor.py` | 6장 | 5주차 | 약 150줄 |
| `w11_simloop.py` | 11장 | 11주차 | 약 150줄 |

## 하는 법

교재의 해당 장을 읽으면서 `raise NotImplementedError(...)` 를 지우고 채웁니다. 각 함수의 docstring 에 무엇을 해야 하는지와 막히기 쉬운 지점이 적혀 있습니다.

채운 뒤 자가 채점을 돌립니다.

```bash
python exercises/check.py w03
```

```
3장 최단경로 자가 채점
----------------------------------------
  [PASS] 세 값을 돌려준다
  [FAIL] NetworkX 와 결과가 같다
         30쌍 중 최대 오차 128.4초 (n1234 → n5678)
  [PASS] 경로가 실제로 이어져 있다
  ...

3/5 통과
```

전부 돌리려면 `python exercises/check.py all` 입니다.

## 채점 기준

`check.py` 가 보는 것은 `tests/` 가 보는 것과 같습니다. **여기를 통과하면 과제 채점도 통과합니다.**

기준을 미리 알려 주는 이유가 있습니다. 이 과목에서 배우는 것 중 하나가 "돌아간다"와 "맞다"를 구분하는 습관입니다. 무엇과 대조해야 맞는 것인지를 아는 것이 그 절반입니다.

| 실습 | 무엇과 대조하는가 |
|---|---|
| 3주차 | NetworkX 의 최단거리와 30쌍 완전 일치 |
| 6주차 | 답을 손으로 아는 작은 시간표 5케이스 + 실제 하남 GTFS 불변식 3개 |
| 11주차 | DTUMOS 엔진과 평균 대기시간 1.5분 이내, 출력 형식 일치 |

6주차의 작은 시간표는 이렇게 생겼습니다.

```
A --(1호선)--> B --(1호선)--> C     08:00 A → 08:10 B → 08:20 C
               |                     08:30 A → 08:40 B → 08:50 C
           도보 약 100m
               |
               D --(2호선)--> E     08:15 D → 08:25 E
```

A 에서 8시에 출발하면 C 는 8시 20분(환승 없음), E 는 8시 25분(환승 1회)입니다. 8시 5분에 출발하면 첫 차를 놓쳐 C 가 8시 50분입니다. 종이에 그려 놓고 확인할 수 있는 크기라 여기서 막히면 어디가 틀렸는지 바로 보입니다.

`smartmob.testing.toy_feed()` 로 이 시간표를 직접 불러 디버깅할 수 있습니다.

## 막힐 때

- **먼저 작은 것으로 확인합니다.** 6주차라면 하남 GTFS(정류장 4,203개) 말고 `toy_feed()`(정류장 5개)로 돌려 봅니다
- **중간값을 찍어 봅니다.** RAPTOR 는 라운드마다 `best` 가 어떻게 바뀌는지 출력하면 대부분 보입니다
- **각 파일을 그냥 실행해도 됩니다.** `python exercises/w03_dijkstra.py` 하면 파일 아래쪽의 `__main__` 이 돌아가면서 하남시청→미사역 결과를 찍습니다
- AI 도구를 써도 됩니다. 다만 나온 코드를 이해하고, 자가 채점이 실패했을 때 어디가 문제인지 짚을 수 있어야 합니다

## 제출

파일 세 개와 함께 짧은 메모를 냅니다.

1. 자가 채점 출력(전부 PASS)
2. 막혔던 지점과 어떻게 풀었는지 3~5줄
3. 11주차는 **자기 루프와 엔진이 왜 완전히 같지 않은지** 한 문단

3번이 중요합니다. 숫자가 다른 것 자체는 문제가 아닙니다. 왜 다른지 모르는 것이 문제입니다.
